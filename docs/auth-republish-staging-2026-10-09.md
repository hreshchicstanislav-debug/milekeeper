## HTTP smoke на новом deployment

15 запросов выполнены через существующую авторизацию Vercel CLI. Защита
deployment не отключалась; ответы принадлежат приложению, а не странице
Vercel Authentication. Реальные пользовательские токены и cookies не использованы.

| Сценарий | Ответ |
| --- | --- |
| `/login`, manifest, icon | 200 |
| `/` и `/items` без сессии | 307 на `/login` |
| `/api/service-events` без сессии | 401 |
| Keep-alive без служебной авторизации | 401; запись не запускалась |
| Sync без Origin или с чужим Origin | 403 |
| Sync с неправильным Content-Type | 415 |
| Sync с пустым body или лишними SDK полями | 400 |
| Sync с нормализованной парой синтетических токенов | 503; cookies не синхронизированы |
| Logout с чужим Origin | 403 |
| Logout без действующей сессии с допустимым Origin | 200, обе auth cookies очищаются |

Ответ 503 синтетической паре воспроизводит уже зафиксированный в инциденте
отказ upstream-валидации. Он показывает прохождение проверки формы двух полей,
но **не подтверждает успешный sync**, действительность сессии или OAuth.
Сервер по-прежнему отклоняет полную SDK Session с лишними полями; исправленный
клиент теперь сокращает её до допустимой пары. Успешная связность этого пути
проверена интеграционным тестом с mock Supabase transport.

За окно проверки runtime logs обнаружены только записи наших негативных
запросов: `Not authenticated` / 401 на service-events и 503 на sync с
синтетическими токенами. Неожиданных серверных ошибок в этом окне не обнаружено.
Это ограниченная smoke-проверка, не длительное наблюдение эксплуатации.
