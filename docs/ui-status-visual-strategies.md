# UI Status Visual Signaling Strategies — Exploration

**Дата создания:** 2025-01-02  
**Цель:** Исследовать возможные стратегии визуальной сигнализации статусов на концептуальном уровне (без принятия решений и конкретных реализаций)  
**Область:** Мобильный UI (Home и Items экраны)

---

## 1. Strategy Overview

Этот документ исследует различные стратегии визуальной сигнализации статусов элементов обслуживания. Каждая стратегия анализируется против критериев из `ui-status-ux-intent.md` и проблем из `ui-status-visual-ux-issues.md`.

**Важно:** Этот документ не выбирает финальное решение и не предлагает конкретные реализации. Он служит для понимания trade-offs различных подходов.

### 1.1. Evaluated Strategies

1. **Single Primary Signal** — один доминирующий визуальный сигнал кодирует статус
2. **Hierarchical Multi-Signal** — первичный сигнал + вторичный поддерживающий сигнал
3. **Text-First Status** — статус в основном кодируется через текст, визуалы как поддержка
4. **Relative vs Absolute Emphasis** — акцент на относительных индикаторах vs конкретных значениях

### 1.2. Evaluation Criteria

Каждая стратегия оценивается против:
- **Glance Mode:** Скорость понимания при беглом просмотре
- **Detail Mode:** Доступность конкретной информации при детальном просмотре
- **Cognitive Load:** Когнитивная нагрузка на пользователя
- **Accessibility:** Доступность для пользователей с различными способностями восприятия
- **Context Appropriateness:** Уместность для контекста (Home vs Items)
- **Mobile Constraints:** Соответствие ограничениям мобильных устройств

## 2. Strategy-by-Strategy Analysis

### 2.1. Single Primary Signal Strategy

**Концепция:** Один доминирующий визуальный сигнал кодирует всю информацию о статусе. Все остальные элементы (текст, дополнительные индикаторы) играют вспомогательную роль или отсутствуют.

**Варианты реализации (концептуально):**
- **Color-only:** Статус передается только через цвет (категория: критический/предупреждающий/нормальный)
- **Text-only:** Статус передается только через текст (конкретное значение: "5 дней", "Просрочено")
- **Symbol-only:** Статус передается только через символы/иконки (например, восклицательный знак, галочка)
- **Shape-only:** Статус передается только через форму (например, круг, треугольник, квадрат)

#### Evaluation Against Criteria

**Glance Mode:**
- ✅ **Сильные стороны:** Один сигнал = быстрое распознавание, минимальная когнитивная нагрузка
- ❌ **Слабые стороны:** Если сигнал — цвет, пользователь с дальтонизмом не сможет понять статус. Если сигнал — текст, требуется чтение (медленнее, чем визуальное распознавание)

**Detail Mode:**
- ✅ **Сильные стороны:** Если сигнал — текст, конкретная информация доступна сразу
- ❌ **Слабые стороны:** Если сигнал — цвет, конкретная информация (количество дней) недоступна без дополнительного текста

**Cognitive Load:**
- ✅ **Сильные стороны:** Минимальная когнитивная нагрузка — один сигнал для обработки
- ❌ **Слабые стороны:** Если сигнал неоднозначен (например, цвет без текста), пользователь должен интерпретировать, что увеличивает нагрузку

**Accessibility:**
- ✅ **Сильные стороны:** Если сигнал — текст, доступность высокая
- ❌ **Слабые стороны:** Если сигнал — только цвет, нарушается WCAG 1.4.1 (Use of Color). Если сигнал — только символ, требуется обучение значению символов

**Home vs Items Context:**
- ✅ **Сильные стороны:** Одинаковый подход на обоих экранах обеспечивает консистентность
- ❌ **Слабые стороны:** Один сигнал может быть недостаточным для разных контекстов (Home требует быстрого понимания, Items — детальной информации)

**Mobile Constraints:**
- ✅ **Сильные стороны:** Минимальное использование пространства
- ❌ **Слабые стороны:** Если сигнал — текст, может потребоваться больше горизонтального пространства

#### Trade-offs Summary

**Основной trade-off:** Простота vs полнота информации
- Простота: один сигнал = минимальная когнитивная нагрузка
- Полнота: один сигнал может не передавать всю необходимую информацию (категория + конкретное значение)

**Риски:**
- Нарушение доступности, если сигнал — только цвет
- Недостаточная информация для принятия решений, если сигнал — только категория
- Медленное понимание, если сигнал — только текст

### 2.2. Hierarchical Multi-Signal Strategy

**Концепция:** Первичный визуальный сигнал передает наиболее важную информацию (например, категорию статуса), вторичный сигнал передает дополнительную информацию (например, конкретное значение или относительное значение).

**Варианты реализации (концептуально):**
- **Primary: Color, Secondary: Text** — цвет передает категорию, текст передает конкретное значение
- **Primary: Text, Secondary: Color** — текст передает конкретное значение, цвет передает категорию как поддержку
- **Primary: Symbol, Secondary: Text** — символ передает категорию, текст передает конкретное значение
- **Primary: Relative Indicator, Secondary: Absolute Value** — относительный индикатор (например, прогресс) передает общее состояние, конкретное значение передает точную информацию

#### Evaluation Against Criteria

**Glance Mode:**
- ✅ **Сильные стороны:** Первичный сигнал обеспечивает быстрое понимание категории
- ⚠️ **Компромиссы:** Вторичный сигнал может конкурировать за внимание, если не организован правильно
- ❌ **Слабые стороны:** Риск конкуренции внимания между сигналами (как в текущей реализации)

**Detail Mode:**
- ✅ **Сильные стороны:** Вторичный сигнал предоставляет конкретную информацию при детальном просмотре
- ✅ **Сильные стороны:** Оба сигнала доступны для полного понимания статуса
- ⚠️ **Компромиссы:** Требуется баланс между визуальным весом первичного и вторичного сигналов

**Cognitive Load:**
- ✅ **Сильные стороны:** Иерархия сигналов помогает организовать информацию
- ⚠️ **Компромиссы:** Два сигнала = больше информации для обработки, но организованной
- ❌ **Слабые стороны:** Риск избыточности, если сигналы дублируют информацию (как в текущей реализации: цвет дважды)

**Accessibility:**
- ✅ **Сильные стороны:** Множественные способы передачи информации повышают доступность
- ✅ **Сильные стороны:** Если первичный сигнал — цвет, вторичный — текст, доступность обеспечена
- ⚠️ **Компромиссы:** Требуется убедиться, что вторичный сигнал не зависит от первичного

**Home vs Items Context:**
- ✅ **Сильные стороны:** Визуальный вес сигналов может адаптироваться к контексту (например, более компактный первичный сигнал на Home)
- ✅ **Сильные стороны:** Вторичный сигнал может быть более детальным на Items
- ⚠️ **Компромиссы:** Требуется баланс между консистентностью и адаптацией к контексту

**Mobile Constraints:**
- ⚠️ **Компромиссы:** Два сигнала могут занимать больше пространства, но организованная иерархия может быть более эффективной
- ❌ **Слабые стороны:** Риск перегрузки при ограниченном пространстве, если сигналы не оптимизированы

#### Trade-offs Summary

**Основной trade-off:** Информационная полнота vs когнитивная нагрузка
- Полнота: два сигнала могут передавать больше информации (категория + конкретное значение)
- Нагрузка: два сигнала требуют больше когнитивных ресурсов, но организованная иерархия может минимизировать нагрузку

**Риски:**
- Конкуренция внимания между сигналами (если иерархия не четкая)
- Избыточность информации (если сигналы дублируют друг друга)
- Перегрузка при ограниченном пространстве

**Ключевой вопрос:** Как обеспечить четкую иерархию, чтобы вторичный сигнал не конкурировал с первичным?

### 2.3. Text-First Status Strategy

**Концепция:** Статус в основном кодируется через текст (конкретное значение или категория в текстовой форме), визуальные элементы (цвет, символы, индикаторы) играют поддерживающую роль для быстрого распознавания.

**Варианты реализации (концептуально):**
- **Text Primary, Color Secondary** — текст передает конкретное значение ("5 дней", "Просрочено"), цвет передает категорию как поддержку
- **Text Primary, Symbol Secondary** — текст передает конкретное значение, символ передает категорию как поддержку
- **Text Only, Visual Hints** — текст передает всю информацию, визуальные элементы только подчеркивают важность (например, жирный шрифт для критических статусов)

#### Evaluation Against Criteria

**Glance Mode:**
- ❌ **Слабые стороны:** Текст требует чтения, что медленнее визуального распознавания (цвет, символ)
- ⚠️ **Компромиссы:** Визуальные элементы как поддержка могут ускорить распознавание, но текст остается основным
- ✅ **Сильные стороны:** Если текст четкий и читаемый, понимание может быть быстрым

**Detail Mode:**
- ✅ **Сильные стороны:** Текст предоставляет конкретную информацию сразу, без интерпретации
- ✅ **Сильные стороны:** Текст однозначен и не требует обучения значению цветов или символов
- ✅ **Сильные стороны:** Текст локализуем и понятен в любом языке

**Cognitive Load:**
- ⚠️ **Компромиссы:** Текст требует больше когнитивных ресурсов для чтения, чем визуальное распознавание
- ✅ **Сильные стороны:** Текст не требует интерпретации или запоминания значений цветов/символов
- ✅ **Сильные стороны:** Текст может передавать как категорию, так и конкретное значение одновременно

**Accessibility:**
- ✅ **Сильные стороны:** Текст доступен для screen readers
- ✅ **Сильные стороны:** Текст не зависит от цветового восприятия
- ✅ **Сильные стороны:** Текст может иметь высокий контраст для читаемости
- ⚠️ **Компромиссы:** Требуется обеспечить достаточный размер шрифта и контраст для читаемости

**Home vs Items Context:**
- ⚠️ **Компромиссы:** Текст может занимать больше пространства, что проблематично для Home (компактность)
- ✅ **Сильные стороны:** Текст может быть более детальным на Items, более компактным на Home
- ✅ **Сильные стороны:** Эмоциональный тон текста может быть более нейтральным (менее тревожным), что подходит для Home

**Mobile Constraints:**
- ❌ **Слабые стороны:** Текст может занимать больше горизонтального пространства, особенно для длинных значений
- ⚠️ **Компромиссы:** Требуется баланс между читаемостью и компактностью
- ✅ **Сильные стороны:** Текст может быть адаптирован к доступному пространству (сокращения, переносы)

#### Trade-offs Summary

**Основной trade-off:** Читаемость vs скорость распознавания
- Читаемость: текст однозначен и понятен
- Скорость: текст требует чтения, что медленнее визуального распознавания

**Риски:**
- Медленное понимание при беглом просмотре (glance mode)
- Занимает больше пространства, особенно на мобильных устройствах
- Может быть менее заметным, чем яркие визуальные сигналы (цвет)

**Ключевой вопрос:** Как сделать текст достаточно заметным для быстрого распознавания, сохраняя при этом читаемость и компактность?

### 2.4. Relative vs Absolute Emphasis Strategy

**Концепция:** Фокус на относительных индикаторах (например, прогресс-бар, процент остатка) vs конкретных значениях (например, "5 дней", "1000 км"). Стратегия определяет, какой тип информации является первичным.

**Варианты реализации (концептуально):**
- **Relative Primary, Absolute Secondary** — относительный индикатор (прогресс, процент) передает общее состояние, конкретное значение доступно при детальном просмотре
- **Absolute Primary, Relative Secondary** — конкретное значение ("5 дней") передается первым, относительный индикатор поддерживает понимание
- **Context-Dependent** — на Home акцент на относительных индикаторах (быстрое понимание), на Items акцент на конкретных значениях (детальная информация)

#### Evaluation Against Criteria

**Glance Mode:**
- ✅ **Сильные стороны (Relative):** Относительные индикаторы (прогресс, процент) быстро распознаются визуально
- ❌ **Слабые стороны (Relative):** Относительные индикаторы требуют интерпретации ("75% от чего?")
- ✅ **Сильные стороны (Absolute):** Конкретные значения ("5 дней") понятны без интерпретации
- ❌ **Слабые стороны (Absolute):** Конкретные значения требуют чтения, что медленнее визуального распознавания

**Detail Mode:**
- ⚠️ **Компромиссы (Relative):** Относительные индикаторы могут быть недостаточными для принятия решений без конкретных значений
- ✅ **Сильные стороны (Absolute):** Конкретные значения предоставляют точную информацию для принятия решений
- ✅ **Сильные стороны (Relative):** Относительные индикаторы помогают сравнить элементы между собой

**Cognitive Load:**
- ⚠️ **Компромиссы (Relative):** Относительные индикаторы требуют понимания контекста (относительно чего?)
- ✅ **Сильные стороны (Absolute):** Конкретные значения не требуют интерпретации
- ⚠️ **Компромиссы (Absolute):** Конкретные значения требуют сравнения между элементами для понимания относительной важности

**Accessibility:**
- ❌ **Слабые стороны (Relative):** Относительные индикаторы (прогресс-бар) могут быть недоступны для screen readers без текстовой альтернативы
- ✅ **Сильные стороны (Absolute):** Конкретные значения доступны через текст
- ⚠️ **Компромиссы:** Требуется обеспечить доступность относительных индикаторов через текстовые альтернативы

**Home vs Items Context:**
- ✅ **Сильные стороны (Context-Dependent):** Разные акценты для разных контекстов могут быть оптимальными
- ✅ **Сильные стороны (Relative on Home):** Относительные индикаторы могут быть более компактными для Home
- ✅ **Сильные стороны (Absolute on Items):** Конкретные значения могут быть более информативными для Items
- ⚠️ **Компромиссы:** Разные акценты могут нарушить консистентность между экранами

**Mobile Constraints:**
- ✅ **Сильные стороны (Relative):** Относительные индикаторы могут быть более компактными
- ❌ **Слабые стороны (Absolute):** Конкретные значения могут занимать больше пространства
- ⚠️ **Компромиссы:** Требуется баланс между компактностью и информативностью

#### Trade-offs Summary

**Основной trade-off:** Скорость распознавания vs точность информации
- Скорость: относительные индикаторы распознаются быстрее визуально
- Точность: конкретные значения предоставляют точную информацию для принятия решений

**Риски:**
- Относительные индикаторы могут быть неоднозначными без контекста
- Конкретные значения могут быть менее заметными при беглом просмотре
- Разные акценты на разных экранах могут нарушить консистентность

**Ключевой вопрос:** Как сбалансировать относительные индикаторы (быстрое распознавание) с конкретными значениями (точная информация) для поддержки обоих режимов (glance и detail)?

## 3. Context Sensitivity (Home vs Items)

### 3.1. Should Home and Items Share the Same Strategy?

**Аргументы за одинаковую стратегию:**
- **Консистентность:** Пользователь ожидает одинакового представления статусов на разных экранах
- **Узнаваемость:** Одинаковые визуальные паттерны облегчают обучение и запоминание
- **Простота:** Одна стратегия проще в реализации и поддержке

**Аргументы против одинаковой стратегии:**
- **Контекстные различия:** Home требует быстрого обзора, Items — детального изучения
- **Информационные потребности:** Home требует компактности, Items может позволить больше деталей
- **Эмоциональный тон:** Home должен быть спокойным, Items может быть более информативным

**Вывод:** Одинаковая стратегия обеспечивает консистентность, но может быть неоптимальной для разных контекстов. Разные стратегии могут быть оптимальными для каждого контекста, но требуют баланса между консистентностью и адаптацией.

### 3.2. Where Divergence is Acceptable or Beneficial

**Приемлемые области расхождения:**

1. **Визуальный вес сигналов:**
   - Home: более компактные, менее заметные сигналы (для спокойного тона)
   - Items: более детальные, более заметные сигналы (для информативности)

2. **Информационная плотность:**
   - Home: только критическая информация (категория + минимальное конкретное значение)
   - Items: полная информация (категория + конкретное значение + относительные индикаторы)

3. **Эмоциональный тон:**
   - Home: менее тревожные цвета/сигналы для критических статусов
   - Items: более информативные цвета/сигналы для всех статусов

**Проблемные области расхождения:**

1. **Семантика статусов:**
   - Одинаковые статусы должны передаваться одинаковыми сигналами на обоих экранах
   - Разные способы передачи одного статуса могут создать путаницу

2. **Базовые визуальные паттерны:**
   - Основные паттерны (например, цветовая схема) должны быть консистентными
   - Разные паттерны могут нарушить узнаваемость

**Вывод:** Расхождение допустимо в визуальном весе и плотности информации, но не в семантике статусов и базовых визуальных паттернах.

## 4. Trade-offs Summary

### 4.1. Cognitive Load vs Information Completeness

**Trade-off:** Минимальная когнитивная нагрузка (один сигнал) vs полная информация (множественные сигналы)

- **Single Primary Signal:** Минимальная нагрузка, но может быть недостаточно информации
- **Hierarchical Multi-Signal:** Больше информации, но требует организации иерархии
- **Text-First:** Полная информация, но требует чтения (больше когнитивных ресурсов)

### 4.2. Speed vs Accuracy

**Trade-off:** Быстрое распознавание (визуальные сигналы) vs точная информация (текст)

- **Color/Symbol Primary:** Быстрое распознавание, но может быть неоднозначным
- **Text Primary:** Точная информация, но требует чтения (медленнее)
- **Relative Indicators:** Быстрое визуальное распознавание, но требует интерпретации

### 4.3. Accessibility vs Visual Impact

**Trade-off:** Доступность (текст, множественные способы) vs визуальное воздействие (цвет, символы)

- **Color-Only:** Высокое визуальное воздействие, но нарушает доступность
- **Text-Only:** Высокая доступность, но может быть менее заметным
- **Multi-Signal:** Баланс доступности и визуального воздействия, но требует организации

### 4.4. Consistency vs Context Optimization

**Trade-off:** Консистентность между экранами vs оптимизация для каждого контекста

- **Same Strategy:** Высокая консистентность, но может быть неоптимальной для разных контекстов
- **Different Strategies:** Оптимизация для каждого контекста, но требует баланса консистентности

### 4.5. Compactness vs Clarity

**Trade-off:** Компактность (минимум пространства) vs ясность (максимум информации)

- **Single Signal:** Максимальная компактность, но может быть недостаточно ясным
- **Multi-Signal:** Больше ясности, но занимает больше пространства
- **Text-First:** Высокая ясность, но может занимать больше пространства

## 7. Conclusion

Этот документ исследовал различные стратегии визуальной сигнализации статусов на концептуальном уровне. Каждая стратегия имеет свои сильные и слабые стороны, и выбор зависит от приоритетов:

- **Если приоритет — минимальная когнитивная нагрузка:** Single Primary Signal
- **Если приоритет — полная информация:** Hierarchical Multi-Signal или Text-First
- **Если приоритет — быстрое распознавание:** Hierarchical Multi-Signal с визуальным первичным сигналом
- **Если приоритет — доступность:** Text-First или Hierarchical Multi-Signal с текстовой поддержкой
- **Если приоритет — контекстная оптимизация:** Relative vs Absolute Emphasis с context-dependent вариантом

**Важно:** Этот документ не выбирает финальное решение. Выбор стратегии должен основываться на приоритетах из `ui-status-ux-intent.md` и учитывать trade-offs, описанные в этом документе.
