## Решение и поведение

Одна карточка в обычном потоке главной, перед пробегом, без автоматических модальных окон и wizard. На каждом рендере выбирается только один актуальный шаг по доступным данным аккаунта. Нет маркера «новый пользователь», localStorage, cookies, аналитики или записи статуса прохождения. Пользователь может сразу пользоваться вкладками, другими формами и существующим обслуживанием.

| Успешно загруженные данные | Карточка / действие |
| --- | --- |
| Нет показаний | Объяснение пользы реального одометра; «Добавить первое показание» / “Add first reading” открывает существующую `AddMileageForm`. Обычная кнопка пробега на этом шаге не дублируется. |
| Есть одометр, нет активных элементов | Предложение выбрать обслуживание и интервал; существующая `AddServiceItemForm` с обычной кнопкой «Добавить элемент» / “Add item”. |
| Есть элемент без последней замены | Название конкретного элемента, объяснение исходной точки интервала; «Указать последнюю замену» / “Record last replacement” ведёт на его существующую страницу. Там пользователь сам открывает обычную форму замены. |
| Замены всех активных элементов известны, положительный средний темп недоступен | Информационный шаг: после реальной поездки добавить большее показание в другой календарный день. Календарные сроки уже работают, км-остаток доступен без среднего темпа. Нет кнопки, требующей немедленно создать историю. |
| Одометр, элементы, последние замены и положительный темп доступны | Карточка отсутствует; обычная главная. |
| Ошибка загрузки | Существующий error boundary, без карточки начала работы и без объявления аккаунта пустым. |

На каждом незавершённом шаге есть вторичная ссылка «Посмотреть демо» / “Explore demo” на `/demo` или `/en/demo`. Использована обычная `<a>`, как на login: без prefetch личных страниц и с завершением личной клиентской оболочки при переходе. Возврат через существующую кнопку «Перейти к своим данным» сохраняет язык, сессию и собственные записи. Демо и его приветствие не изменялись.

Последняя замена необязательна: текст прямо разрешает оставить элемент без записи, если дата/пробег неизвестны. Отсчёт такого элемента пока недоступен, остальные функции работают. Нет фиктивной замены сегодня, автоматического сохранения или переноса demo. Если не заполнено несколько элементов, предлагается первый из существующего списка, отсортированного загрузчиком по названию; остальные не скрываются в разделе элементов.

Календарный элемент с одной записью одометра и известной заменой уже рассчитывается существующим движком. Информационная карточка об истории лишь объясняет ещё недоступный средний темп, не объявляет календарный расчёт неработающим и не требует дополнительных записей.

## Фактическая реализация

- `src/lib/home/gettingStarted.ts`: чистый выбор следующего UI-состояния; принимает уже загруженные данные и **готовый** `dailyRate` от `calculateDailyMileageRateToBe`. Не содержит формул прогнозирования и не считает достаточность по числу строк.
- `src/app/components/HomeGettingStarted.tsx`: локализованная карточка и существующие формы/ссылки. Названия личных элементов выводятся без перевода.
- `src/app/page.tsx`: подключение после обоих этапов загрузки и обычного расчёта темпа. Пока есть карточка, прежняя общая подсказка `HomeAdaptiveContent` о частом вводе не дублируется; карточка пробега, средний темп, обслуживание и остальные функции сохраняются.
- `AddMileageForm`: необязательный текст кнопки для первого показания; отдельный `data-add-mileage-trigger` для правильного возврата фокуса. Это важно при соседстве формы создания элемента и обычной кнопки пробега. Валидация, сохранение, revalidation, работа дат не изменены.
- RU/EN в существующих `src/lib/copy/ru.ts` и `src/lib/i18n/en.ts`. CSS только для карточки, с переносом текста, вертикальными действиями и доступными touch targets.

### Как отличаем отсутствие данных от ошибки

Главная уже использует `Promise.allSettled` для максимального одометра, истории из 50 записей и активных элементов. При ошибке любого чтения в личном режиме она выбрасывает ошибку, а не подменяет результат пустыми массивами. Загрузка последних событий отдельным зависимым запросом тоже выбрасывает ошибку. Это поведение сохранено.

Selector вызывается только после завершения этих запросов. Флаг `loaded` разрешён только при отсутствии отклонений первого этапа; даже существующий dev-guest auth fallback не показывает onboarding. Дополнительно проверяются согласованность наличия максимального показания с непустой историей и наличие явного ключа для каждого элемента в карте последних событий. Отсутствующий ключ не приравнивается к успешному `null`. При несогласованных независимых чтениях карточка скрывается до следующего чтения.

Новых запросов или изменений загрузчиков нет. Пустой список означает отсутствие **активных** элементов, а не доказательство, что человек никогда не пользовался аккаунтом. После удаления своих данных карточка может вернуться. Проверка не создаёт транзакционный снимок, но избегает ложного приглашения при обнаруженной несогласованности.

## Ограничения и ручная приёмка

- Реальный Google consent с новым/истёкшим Google-аккаунтом не выполнялся. Автоматические регрессии проверяют прежний provider `google`, общий callback, locale, guards, login/logout и сохранение сессии через локальный mock provider. Реальный Google OAuth остаётся для ручной проверки владельца.
- Существующий `error.tsx` вызывает `reset()` без перезапроса серверных данных. При инъекции ошибки восстановление подтверждено через reload; кнопка «Повторить» не инициировала новое чтение. Глобальное поведение error boundary в этом scope не менялось.
- В dev-логах остаётся прежнее предупреждение синхронного `cookies().get` из `appCookieBridge.ts` / `getAppNow`; в build — deprecated middleware convention. Эти файлы не менялись. 14 старых TS-ошибок перечислены в сохранённых baseline-логах.
- История для темпа по-прежнему ограничена существующими 50 записями и правилами движка; часовые зоны, freshness, confidence, календарная строка даты и другие описанные в анализе ограничения не исправлялись. Новых обещаний точности/уведомлений/автоматического одометра нет.
- Неизвестная замена не записывается и не помечается как известная. Карточка может оставаться, пока сведения отсутствуют; отдельного постоянного dismissal нет, остальные функции доступны.
- Нет реального устройства/PWA-установки или нового исследования понимания текстов. Мобильная проверка выполнена Chromium viewport и визуальным просмотром screenshots.

Auth, Supabase-клиенты, RLS, миграции, server actions и расчётные алгоритмы не изменялись. Production не затрагивался. Deployment, promotion, push и merge не выполнялись. Изменения оставлены в feature-ветке для ручной проверки.
