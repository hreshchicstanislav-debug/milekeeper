# MileKeeper — Onboarding, Slice 1: отчёт

Дата: 2026-10-09. Репозиторий: `/Users/stanislav/Mile_keeper`. Ветка: `codex/onboarding-demo`, создана от `e3aaa44` на актуальной `codex/english-localization`; локализация и оба исследовательских документа сохранены. `main` не использовалась как база: она отстаёт от опубликованной RU/EN-версии.

## Реализованный объём

Согласованное решение записано в [03-approved-scope.md](03-approved-scope.md). Оно отделяет утверждённый Slice 1 от предварительных предложений будущих этапов.

- Экран входа предлагает «Посмотреть демо» / «Войти через Google» и “Explore demo” / “Continue with Google”. Google-вход доступен независимо от демо; его обработчик, provider и callback сохранены.
- Публичные `/demo` и `/en/demo` открывают заполненный пример без Google или Supabase Session. EN использует существующий механизм rewrite и request locale.
- Отдельная оболочка MileKeeper: постоянная sticky-маркировка «Демонстрация · вымышленные данные», оценка пробега, последний замер, темп, ближайшее обслуживание и пять элементов. Нет фиктивной навигации и неработающих действий.
- Тексты объясняют факт и оценку, прогноз по пробегу и срок по календарю. Ссылки возврата ведут на локализованный login; существующий AuthGate открывает личную главную для вошедшего пользователя.
- Переключатель RU/EN работает внутри примера, включая reload и Back/Forward. В демо он не записывает языковую настройку основного приложения.

## Расчёты и время

В [snapshot.ts](../../src/lib/demo/snapshot.ts) создаётся проверенный набор из предложения 02: семь показаний одометра, пять элементов, последнее обслуживание каждого известного элемента и старое событие масла. Снимок каждый раз создаётся заново в памяти.

Использованы действующие чистые функции без изменения формул: `calculateDailyMileageRateToBe`, `computeEstimatedOdometer`, `calcServiceStatus`, `buildServiceItemStatusVM`, `sortByUrgency`, `pickSoonMaintenanceItems`.

Тот же снимок проверен при серверных TZ `UTC`, `Asia/Almaty`, `America/Los_Angeles`.

## Изоляция и переиспользование

[AppShell](../../src/app/components/AppShell.tsx) минимально выделен из root layout. На двух точных демомаршрутах он не монтирует AuthGate, TopBreadcrumbsBar, BottomNav и ScrollLockRouteGuard. На личных маршрутах сохраняет прежний состав оболочки. Переходы вход/выход из демо используют обычные ссылки без prefetch личных страниц.

[Middleware](../../src/middleware.ts) разрешает только `/demo` и `/en/demo` до чтения/обновления auth-токенов. Даже истёкшая сессия на демо не обновляется, не удаляется и не подменяется. `/demo/items`, похожие префиксы, `/items`, `/history`, детали и главная остаются защищёнными. В Slice 1 дополнительных демомаршрутов нет.

В контуре демо нет импорта data actions, Supabase-клиентов, AppMode/AppNow и нет форм записи. Числа создаются из синтетического набора, а не загружаются из аккаунта. Не создавались demo-пользователи, записи в БД, seed, миграции или новые серверные действия; OAuth provider и RLS не менялись.

Переиспользованы `LocaleProvider`, `LanguageSwitcher`, `StatusRowCompact`, `StatusRowDetail`, существующая локализация статусов, кнопка `add-mileage-button`, цвета, типографика, радиусы и мобильный canvas 430 px. Общие статусные компоненты и бизнес-формулы не изменены. Новый EN-формат ближайших сроков работает только в демо; RU использует прежний вывод чистого helper.

## Ограничения и наблюдения

- Один ранний полный production-прогон сообщил React hydration error #418 без привязки к маршруту. Два последующих полных прогона с логированием URL, включая заключительный после всех UI-уточнений, прошли без ошибки; причина не установлена. Это наблюдение не скрыто и не объявлено исправленным. Демо отдельно прошло проверки консоли и изоляции. При ручной проверке обратить внимание на reload, вход/выход и переключение языка.
- Старые 14 TS-ошибок находятся только в пяти fixtures расчётных тестов: обязательные `user_id` и несуществующий экспорт `ServiceStatusResult`. Они не исправлялись. Настройки проверки типов не ослаблялись. Предупреждение Next о middleware → proxy сохранено.
- Это замороженный пример, а не текущая дата автомобиля. При выборе другого D нужно перепроверить календарный интервал с исключением 29 февраля. Весь продукт на единую модель часовых поясов не переводился.
- Browser smoke использует Chrome и мобильные размеры viewport; физические iPhone/Android и Safari отдельно не проверялись. Настоящий Google OAuth в production не запускался: его сохранность подтверждена кодом, unit-тестом и прежним полным локальным mock-сценарием.
- Slice 2 не начат: нет слайдов, добавления показания, «через неделю», редактирования, полноценных форм и помощи после Google-входа.

## Ручная приёмка и повторение

Slice 1 реализован и готов к ручной проверке; итоговые unit, dev/production browser smoke и обычная production-сборка прошли. Запуск из репозитория: `npm run dev`, далее `http://localhost:3001/login`, `/demo`, `/en/demo`. Проверить оба входных действия, мобильные размеры, язык, маркировку после прокрутки и выход к своему аккаунту. Демо не создаёт и не переносит данных. Временные серверы проверки остановлены.

Повторение: `npm test`, `npx tsc --noEmit --incremental false`, `npm run build`. Browser smoke: `npm run test:i18n:browser`; при внешней установке Playwright задать `MILEKEEPER_PLAYWRIGHT_PATH`, как описано в существующем i18n-отчёте. Для production smoke сначала собрать с env локального fixture, затем `MILEKEEPER_I18N_PRODUCTION=1`; после проверки повторить обычный `npm run build`, чтобы mock env не оставался в локальной сборке. `.env.local` не изменяется.
