## Реализовано

Короткое приветственное native `<dialog>` только внутри публичного `/demo` и `/en/demo`. При первом открытии без маркера закрытия появляется автоматически; крестик, основная кнопка и Escape закрывают его на текущем демоэкране. «О MileKeeper» / “About MileKeeper” повторно открывает окно без изменения демонстрационного снимка.

Согласованные RU/EN-тексты сохранены полностью, включая описание прогноза и явное указание на вымышленные данные. Переключатель языка внутри окна использует существующую навигацию, переводит открытое окно без перемонтирования или потери состояния. Он не сохраняет языковое предпочтение основного приложения.

Первый SSR и первый клиентский render одинаковы: окно закрыто, обращений к storage нет. `useEffect` после hydration читает `milekeeper.demo.welcome.v1`. Только при закрытии записывается значение `seen`, общее для RU и EN. Refresh и последующие посещения после закрытия не вызывают автоматического показа. В storage не сохраняются демоданные, сессия или настройки аккаунта. Чтение, запись и сам доступ к localStorage защищены `try/catch`. При отказе storage демо и ручное открытие/закрытие работают; на новой загрузке приветствие может появиться снова.

Окно использует существующие цвета, радиусы и основную кнопку MileKeeper. Ширина до 430 px, внешние отступы 16 px; на низком viewport содержимое прокручивается внутри диалога. Native top layer делает фон inert; Tab/Shift+Tab остаются внутри окна. Начальный фокус — на крестике; при закрытии фокус возвращается к открывшему элементу, а при автоматическом показе — к «О MileKeeper». Переиспользован чистый UI-helper `scrollLock` с восстановлением прокрутки. Анимаций нет, включая режим reduced-motion.

## Изоляция

Новые компоненты импортируют только React, существующую локализацию, чистый UI scroll helper и локальные тексты/storage helper. Не переиспользован общий account `ModalSheet`, чтобы не подключать его личное сохранение locale и учёт состояния модальных окон. Нет Supabase-клиента, API, auth-sync, server actions, создания сессии или форм записи. Приветствие не монтируется на Google-входе, callback или в аккаунте. Middleware, AuthGate, Google OAuth, Supabase, миграции, формулы, синтетический набор и AppNow не изменены.

Браузерные проверки измеряют все запросы браузера и локального provider, включая серверные обращения. Во время приветствия и демо у гостя и авторизованного fixture-пользователя нет provider-запросов, личных API, POST или server actions. Cookies и sessionStorage сохраняются; единственное новое значение localStorage — маркер закрытия. Существующий marker повторное открытие не изменяет. Внешняя сеть в browser smoke блокируется; реальные пользовательские данные не используются.

## Ограничения и ручная проверка

- Ранее отмеченная единичная React #418 воспроизвелась в первом production smoke на `/en/demo` в сценарии существующего демо после проверки приветствия. Этот прогон завершился FAIL, ошибка не скрывалась. Повторный полный production smoke и дополнительная диагностика из 16 циклов прошли без неё. Причина не установлена, устранение этой периодической ошибки не заявляется. Первая загрузка, refresh и быстрое переключение RU/EN остаются обязательными пунктами ручной приёмки.
- Проверки выполнены в Chrome с мобильными viewport. Физические iPhone/Android и Safari не проверялись; отдельно проверить native dialog, прокрутку и клавиатуру на целевых устройствах. Настоящий Google OAuth не запускался: его код сохранён, прежние unit и локальные mock-сценарии проходят.
- Маркер зависит от browser storage и origin: очистка данных, приватное окно, другой браузер или другой deployment origin могут вызвать новый показ. При недоступном storage повторный автоматический показ после новой загрузки является ожидаемым fallback.
- Новые зависимости не добавлялись. 14 старых TS-ошибок, несовместимый lint и предупреждение Next о middleware → proxy сохранены. Slice 2 не начат.
