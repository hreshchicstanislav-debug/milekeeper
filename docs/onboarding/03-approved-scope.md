# MileKeeper — согласованный объём onboarding

Дата: 2026-10-09. Основание: прямые решения владельца продукта для Slice 1 и Slice 1.5 (Welcome Intro). Исследование: [01-product-analysis.md](01-product-analysis.md); предварительное предложение: [02-onboarding-proposal.md](02-onboarding-proposal.md).

## Утверждённый первый вход

Вариант А: существующий экран входа предлагает два независимых действия:

| RU | EN | Результат |
| --- | --- | --- |
| Посмотреть демо | Explore demo | Публичный пример без авторизации |
| Войти через Google | Continue with Google | Существующий Google OAuth |

Демо добровольно. Google-вход не требует просмотра примера и сохраняет прежний provider, callback и работу с сессией.

## Цель и границы

Помочь понять пользу MileKeeper: измеренный пробег является фактом, расчётный пробег и сроки по пробегу являются оценкой, обслуживание может быть близким, просроченным или без достаточных данных. Публичное демо позволяет увидеть заполненный продукт до передачи своих данных.

Изоляция обязательна: синтетический набор живёт только в коде и памяти отдельной страницы. Нет demo-пользователя, Supabase-записей, seed, server actions, личных data API, auth-sync, токенов, общей настройки TEST/AppNow. Это действует и для уже вошедшего посетителя. Публичный доступ разрешается только реализованным `/demo` и `/en/demo`; остальные страницы сохраняют защиту. Демоданные не переносятся в аккаунт.

Slice 1 и Slice 1.5 не включают слайды, добавление показания, «через неделю», редактирование, формы и шаги после входа. Не реализованные разделы не показываются как доступная навигация. После Slice 1.5 работа останавливается; deployment/promotion требуют отдельного разрешения. Ранее подготовленный отдельный staged deployment Slice 1 этим решением не обновляется.

## Slice 1.5 — Welcome Intro

Только `/demo` и `/en/demo`: при первой загрузке без маркера закрытия автоматически открыть компактное окно. На сервере и при первом клиентском render окно закрыто; localStorage читается только после hydration. До закрытия маркер не записывается. Закрытие не меняет маршрут или демонстрационный снимок. При refresh/повторном посещении после закрытия окно автоматически не показывается. Один общий ключ `milekeeper.demo.welcome.v1` со значением `seen` для RU/EN; единственная разрешённая новая запись localStorage. Это локальный маркер браузера для текущего origin, не данные аккаунта.

Кнопка «О MileKeeper» / “About MileKeeper” внутри демо повторно открывает окно без сброса данных. RU/EN доступен также внутри окна; переключение переводит открытое окно, сохраняя его состояние и не записывая языковое предпочтение личного приложения. Маркер закрытия остаётся общим. При отказе localStorage чтение/запись обрабатываются без ошибки: окно можно закрыть и пользоваться демо; после новой загрузки оно может появиться снова, поскольку сохранять маркер негде.

Согласованная доработка Slice 1.5: две кнопки вертикально с небольшим промежутком. Основная остаётся синей, закрывает окно и продолжает демо. Вторичная использует существующий нейтральный стиль с рамкой и обычную ссылку на `/` для RU или `/en` для EN, без prefetch. Нажатие сохраняет тот же маркер `seen`, как остальные способы закрытия. Авторизованный посетитель открывает свой существующий аккаунт; гость перенаправляется прежней защитой на `/login` или `/en/login`, где остаётся Google OAuth. Само демо не выполняет auth-sync, sign-out, Supabase/API-запросы и не переносит пример в аккаунт. Описания, крестик, повторное открытие и общая логика storage сохраняются. Обе кнопки доступны при прокрутке на 320×360; клавиатурный цикл включает вторичное действие. Приёмка включает RU/EN × гость/аккаунт, отсутствие личной сети до выхода, сохранение сессии и Google OAuth, а также регрессию React #418.

Границы: одно окно, без wizard/слайдов, гарантии точности, автоматического считывания одометра или push-уведомлений. Не монтируется на login, callback или в личном аккаунте. Нет Supabase, создания сессии, auth-sync, личных API, server actions, записей в БД, изменений AppNow/TEST, расчётных формул и синтетического набора Slice 1. Остальные экраны и их дизайн сохраняются.

Приёмка: новый посетитель RU и EN видит окно; все три способа закрытия работают; refresh/повторное посещение/смена языка после закрытия не вызывают нового показа; повторное открытие сохраняет пример. Клавиатурный фокус остаётся внутри окна, после закрытия возвращается; фон не прокручивается, содержимое доступно на низком экране. Читаемость от 320 px и на desktop, отсутствие горизонтального скролла и обрезания EN; reduced-motion соблюдается (анимаций нет). Проверить первую загрузку и refresh на React #418, отсутствие console/hydration errors и личной сети для гостя и вошедшего посетителя, отказ localStorage, прежний Google-вход и личный аккаунт. Все unit-тесты, dev/production browser smoke и production build; TypeScript сравнить с baseline из 14 старых ошибок. Локальный commit после проверок, без push/merge/deployment/promotion и без Slice 2.

## Что ещё не утверждено

Предложение 02 не является целиком утверждённым ТЗ. Кроме явно согласованного приветствия Slice 1.5, остаются открытыми число и тексты остановок, порядок действий, интерактивный сценарий, локальное сохранение/сброс демоданных, повторный запуск расширенного onboarding, глубина истории/расчётов, механика помощи после входа, метрики onboarding и будущие правила демонстрационных часов.

Технический выбор Slice 1: замороженный день D = 2026-10-09, показанный в интерфейсе. Все даты создаются относительно D в одной серверной зоне календарных дней, расчёты выполняются на сервере; браузер получает числа и календарные строки. Это воспроизводимый снимок, не обещание одинакового календарного результата для произвольных D или модель часовых поясов всего приложения. Будущая смена D требует повторной проверки календарного примера с исключением 29 февраля.
